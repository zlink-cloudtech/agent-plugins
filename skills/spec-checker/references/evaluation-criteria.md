# PRD 评审维度与标准

从以下维度对 PRD 文档进行打分（1-5分，5分为最优），严格依据标准打分。

## 一、需求生成结构和规范评估（权重 10%）

评审 PRD 文档结构是否符合规范，章节是否完整。

### PRD 必备章节

| 章节 | 要求 |
|------|------|
| 概述 | 必填 |
| 问题陈述 | 必填 |
| 核心价值目标 | 必填 |
| 场景使用约束 | 必填 |
| 核心价值场景分析/用户故事 | 必填 |
| 边界分析 | 必填 |
| 功能需求 | 必填 |
| 成功标准 | 必填 |
| 假设 | 必填 |
| 依赖项 | 可选 |
| 待解决问题 | 可选 |

## 二、内容章节完整性评估（权重 20%）

### 2.1 概述与问题陈述完整性（4%）

- 概述是否用1-2句话概括功能是什么、解决什么核心用户问题
- 问题陈述是否清晰描述当前痛点、用户场景背景

### 2.2 核心价值目标完整性（4%）

- 价值目标是否列出2-5个核心价值点
- 价值目标是否包含可量化的目标指标

### 2.3 用户故事内容完整性（8%）

每个用户故事需包含：

- **用户故事描述**（必填）：As a / I want to / So that 格式，该描述本身即为场景描述（xx人员在xx背景下，做了xx操作，得到了xx预期效果）
- **优先级理由**（必填）：阐述该故事的价值以及为何处于此优先级
- **价值验收标准**（必填）：必须清晰、量化、可验收
- **验收场景**（必填）：Given/When/Then 格式，聚焦细节的效果验证
- **模块相关性**（可选）：说明与本模块功能的关联关系

### 2.4 边界分析完整性（4%）

- 容量边界是否明确（如最大数量、上限值）
- 输入输出边界是否明确（如字段长度、取值范围）
- 系统资源约束是否明确（如CPU、内存、磁盘占用）
- 边界场景是否明确异常边界处理方式
- 边界是否为本模块新增约束，避免重复现有模块已有规格

### 2.5 功能需求完整性（4%）

- 功能需求编号是否按 FR-1、FR-2 顺序编号
- 功能需求描述是否面向业务干系人编写，不含实现细节
- 验收标准是否包含可测试的条件 checkbox

## 三、需求内容准确性评估（权重 70%）

### 3.1 用户故事内容准确性（35%）

- 场景描述是否清晰：角色、背景、操作、预期效果四要素完整
- 优先级理由是否充分：价值阐述清晰，优先级排序有依据
- 价值验收标准是否量化：必须清晰、量化、可验收，不能出现模糊表述
- 验收场景是否聚焦细节：Given/When/Then 格式，聚焦效果验证而非实现过程
- 验收场景覆盖度：是否覆盖正常流程、异常流程、边界场景
- 模块相关性：用户故事是否与本模块功能强相关，避免描述其他模块已有能力

### 3.2 功能需求内容准确性（20%）

- 功能需求描述是否具体：不能出现二义性内容
- 验收标准是否可测试：每个 checkbox 可明确验证通过/不通过
- 规格约束是否明确：涉及数值约束的必须写具体数值，范围和默认值清晰
- 约束场景是否明确：明确不支持的场景和效果

### 3.3 边界与约束准确性（10%）

- 容量边界是否参照现有版本标准：必须遵从现有的规格约束
- 输入输出边界是否有明确数值：字段长度、取值范围必须量化
- 系统资源约束是否合理：不能无限申请资源，需给出明确限制
- 边界场景处理是否明确：异常场景的处理方式清晰可执行
- 边界与模块相关性：边界约束必须为本模块新增内容

### 3.4 成功标准准确性（5%）

- 成功标准是否可衡量：每项必须能在不了解实现细节的情况下验证
- 成功标准是否量化：包含具体的数值、比例、时间等指标
- 成功标准是否用户导向：描述用户或业务成果，而非系统内部实现
