# PRD 质量评审（Spec Checker）

三维度并行委托子Agent评审，主Agent汇总加权评分，输出结构化评审报告。

## 原则

- **严苛打分**：不宽松，每个扣分项必须有具体依据。
- **并行优先**：三个维度同时评审，最大化利用隔离上下文。
- **证据驱动**：每个扣分项必须附带 PRD 原文摘录。
- **建议可执行**：每个问题必须给出具体的改进建议。

## 工作流程

### Phase 1：并行委托三维度评审

确认 PRD 文件路径后，提取 PRD 摘要（≤300字），同时发起3个子Agent：

**Agent 1 — 结构规范**（权重 10%）：

```markdown
从"结构规范"维度评审 PRD。权重：10%。

PRD 路径：[path]

检查标准：
1. 是否包含概述与问题陈述？
2. 是否包含核心价值目标？
3. 是否包含用户场景/用户故事？
4. 是否包含功能需求（FR）？
5. 是否包含成功标准？
6. 是否包含假设与约束？
7. 章节编号是否规范（无跳号、无重复）？

逐项评分（0-5），每个扣分项必须引用 PRD 原文说明缺失了什么。

输出：
## 维度：结构规范
| 检查项 | 评分 | 原文摘录/缺失说明 |
|--------|------|-----------------|
...
维度得分：X/5
```

**Agent 2 — 内容完整性**（权重 20%）：

```markdown
从"内容完整性"维度评审 PRD。权重：20%。

PRD 路径：[path]

检查标准：
1. 概述是否清晰描述了问题背景和业务目标？
2. 核心价值目标是否可衡量？
3. 用户场景是否覆盖主路径和异常路径？
4. 边界情况是否考虑（极端输入、并发、故障恢复）？
5. 功能需求是否有对应的验收标准？
6. 是否有明确的不在范围内声明？

逐项评分（0-5），每个扣分项必须引用 PRD 原文说明缺失了什么。

输出：
## 维度：内容完整性
| 检查项 | 评分 | 原文摘录/缺失说明 |
|--------|------|-----------------|
...
维度得分：X/5
```

**Agent 3 — 内容准确性**（权重 70%）：

```markdown
从"内容准确性"维度评审 PRD。权重：70%。

PRD 路径：[path]

检查标准：
1. 每个 FR 是否有可测试的验收标准（非抽象描述）？
2. FR 之间有无逻辑冲突？
3. 场景中的 Given/When/Then 是否可执行？
4. 成功标准是否可度量（有具体数字，非"性能好"）？
5. 假设是否有依据？约束是否合理？
6. 术语使用是否一致（同一概念不用多个名称）？
7. 是否有 [TBD]/[TODO] 占位符？

逐项评分（0-5），每个扣分项必须引用 PRD 原文。

输出：
## 维度：内容准确性
| 检查项 | 评分 | 原文摘录 | 问题说明 |
|--------|------|---------|---------|
...
维度得分：X/5
```

「并行分发」三个子Agent「在隔离环境中执行」。

### Phase 2：汇总评分

收到三份子Agent评审结果后，计算加权总分：

```
加权总分 = (结构得分/5 × 0.1 + 完整性得分/5 × 0.2 + 准确性得分/5 × 0.7) × 10
```

等级：优秀 ≥ 9.0 / 良好 ≥ 7.5 / 需改进 ≥ 6.0 / 不合格 < 6.0

### Phase 3：输出评审报告

加载 `assets/report-template.md`，填入：
- 三维度各自得分和加权总分
- 合并不符合项到"评审建议汇总"
- 最终评审结论

输出路径：`docs/reviews/review-<PRD_SHORT_NAME>-<YYYYMMDD>.md`

## 行为规则

- 三个子Agent必须并行发起，不串行
- 子Agent使用 PRD 路径（不传全文），由其自行读取
- 若某子Agent返回不完整，追问补全后再汇总
- 汇总评分时使用子Agent报告中的维度得分（原始分数），不重新评分
