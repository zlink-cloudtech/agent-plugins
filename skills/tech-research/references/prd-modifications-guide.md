# PRD 修改建议编写指南

预研完成后，将预研发现映射到 PRD 的具体修改建议。每条修改建议应让 PRD 维护者可以直接执行。

## 修改建议格式

每条修改建议使用以下结构：

```markdown
## 修改N：[一句话标题]

**位置**：§章节名
**修改类型**：新增 / 修改 / 替换 / 删除

**当前内容**：
> [引用原文，保持原始格式。如果是新增内容则写"（无）"]

**建议修改为**：
> [修改后的完整文本。确保替换后上下文通顺]

**修改理由**：[预研发现 + 为什么需要这样修改]
```

## 修改类型映射

根据预研发现的性质，选择合适的修改类型和目标章节：

| 预研发现 | 修改类型 | 目标章节 |
|----------|----------|----------|
| "待解决问题"中的技术选型已决策 | **修改** | §待解决问题 — 标记"已决策"，移动到"技术决策记录" |
| "技术评估参考"阶段结束 | **替换** | §技术评估参考 → §技术决策记录 |
| 新发现的外部依赖 | **新增** | §依赖项 |
| 新发现的技术约束 | **新增** | §假设 或 新增 §风险 |
| PRD 假设被预研推翻 | **修改** | §假设 — 更新为预研确认的状态 |
| FR 实现方式需要明确 | **修改** | §功能需求 — 补充实现级验收标准 |
| 容量/资源约束已验证 | **新增** | §边界分析 — 新增预研验证表 |
| CLI/工具注入方式明确 | **修改** | §FR 验收标准 — 补充具体方式 |

## 常见修改模式

### 模式1："待解决问题"→"已决策"

```
## 修改1：执行引擎选型标记为已决策

**位置**：§待解决问题
**修改类型**：修改

**当前内容**：
> - 执行引擎选型（自研 vs `act` 适配）需在原型验证后决策

**建议修改为**：
> - 执行引擎选型已决策：全自研轻量调度器（详见 §技术决策记录）

**修改理由**：预研确认 act 强制依赖 Docker，CLI 运行在平台容器内产生 Docker-in-Docker 问题。
```

### 模式2：新增技术决策记录

```
## 修改2：技术评估参考替换为技术决策记录

**位置**：§技术评估参考
**修改类型**：替换

**当前内容**：
> [原技术评估参考全文]

**建议修改为**：
> ## 技术决策记录
> 
> ### TD-1：执行引擎采用全自研
> **决策日期**：YYYY-MM-DD
> **决策理由**：...

**修改理由**：预研完成，"评估"阶段已结束，应转为"决策"记录。
```

### 模式3：新增依赖

```
## 修改3：新增 Docker socket 依赖

**位置**：§依赖项
**修改类型**：新增

**当前内容**：
> （无）

**建议修改为**：
> - 多镜像 Job 执行依赖 Docker socket 挂载（DooD 模式）。若 CI 节点未挂载 /var/run/docker.sock，多镜像流水线降级为仅支持默认镜像

**修改理由**：预研发现多镜像 Job 需通过 Docker socket 启动新容器。
```

### 模式4：新增风险

```
## 修改4：新增平台环境风险

**位置**：§依赖项之后
**修改类型**：新增

**当前内容**：
> （无）

**建议修改为**：
> ## 风险与缓解
> 
> | 风险 | 影响 | 缓解 |
> |------|------|------|
> | CI 节点未挂载 Docker socket | 多镜像流水线无法执行 | 降级为同镜像执行 + 文档说明 |

**修改理由**：预研识别出该环境依赖风险。
```

## 修改建议汇总

所有修改建议完成后，生成汇总表：

```markdown
## 修改汇总

| 编号 | PRD 位置 | 修改类型 | 影响等级 |
|------|----------|----------|----------|
| 1    | §待解决问题 | 修改 | 低 |
| 2    | §技术评估参考 | 替换 | 中 |
| 3    | §依赖项 | 新增 | 中 |
```

## 编写要点

1. **精确引用原文**：当前内容必须与 PRD 原文一致，否则修改无法执行
2. **提供完整新文本**：建议修改为的部分是可独立替换的完整段落，而非"在某某处插入一行"
3. **理由基于预研事实**：不是"我觉得应该改"，而是"预研发现 X，因此 Y 需要调整为 Z"
4. **优先高影响修改**：影响等级中/高的修改放前面
5. **不多改**：只改预研有发言权的部分，不借机"顺便优化"PRD 文案或结构
