# 技术规格模板

加载 `references/techspec-template.md` 并按以下规则填充。

## 填充规则

**元信息**：
- 列出实际读取的所有架构文档路径
- 版本范围：由 Controller 从 DEP_YAML.doc_header.version_range 自动注入，不手工编写

**需求矩阵**：
- 按优先级排序（P0 在前），同优先级按依赖顺序排列
- YAML 格式的依赖信息由 Controller 在§服务依赖与开发路线中统一注入（见依赖分析双格式放置规则），需求矩阵节不再单独展示依赖图
- FR 全覆盖验证表：逐条 FR 确认覆盖 SR

**关键流程设计**：
- 至少覆盖所有 P1 SR 的 happy path 时序图
- 异常路径仅在涉及多服务协作时绘制
- 状态机仅在有资源生命周期管理需求时包含

**数据模型设计**：
- 每个实体必须有"用途"说明和完整字段表
- CRD 字段路径以 spec./status. 为前缀
- 实体关系图覆盖所有建模实体

**系统需求详述**：
- 每个 SR 严格遵守"描述什么，不描述怎么做"的边界
- "对外接口"节只在有其他 SR 消费时才包含
- "依赖接口"节只在消费其他 SR 时才包含
- 验收条件使用 BDD 格式：`**Given** [前置状态]，**When** [触发操作]，**Then** [可观测结果]`

**依赖分析（YAML 为单一来源）：**
- Controller 传入 YAML（来自 dependency-analyzer）和 Mermaid（由 `yaml-to-mermaid.js` 从 YAML 生成）
- §服务依赖与开发路线中只放置 YAML + Mermaid 两种格式，不额外放置 ASCII 图、可并行开发组表、P1 关键路径 ASCII（这些信息均在 YAML 中以结构化数据存在）
- 放置顺序：YAML 块 → Agent 标注 → Mermaid 块 → Agent 标注
- YAML 块前标注：`> **⚠️ Agent 注意：** 下方 YAML 块是依赖分析的唯一可信数据源。处理本节时请只解析 YAML，可完全跳过下方的 Mermaid 图。`
- Mermaid 块前标注：`<!-- ↓ 以下 Mermaid 为人工阅读辅助，Agent 请忽略 ↓ -->`

**省略规则**：
- 无需建模的流程 → 省略"关键流程设计"节中的对应子节
- 无状态机需求 → 省略"状态机"子节
- 无数据模型变更 → 省略"数据模型设计"节
- 无架构挑战 → 省略"架构分析"节
- 无跨服务接口 → 省略"接口契约变更汇总"节
- 无未解决问题 → 省略"开放问题"节
- 任何 SR 无跨服务消费/依赖 → 省略该 SR 的"对外接口"/"依赖接口"节
